RLS 方針

  • 全テーブルで RLS 有効。自分の行 (auth.uid()) のみ操作可。user_metadata は使わない。
  • anon の権限は全て剥奪。authenticated には列単位の GRANT で最小限のみ付与。
  • coins / score / level / exp / 日次判定日 / list.status / spent_amount / user_items の insert は API (service_role) のみ。
  • items は認証済みユーザーの select のみ。

仮決め・要確認

  1. 通貨は別テーブルにせず profiles に同居 (1:1 で更新が 1 行で済むため)。
  2. list.status と spent_amount はクライアント更新不可。開始・終了は API 経由。
  3. 未完了リストは 1 ユーザー 1 つに制限。複数同時に作る要件があれば外す。
  4. リスト作成・閲覧ポイントを 1 日 1 回とし last_list_reward_on を追加。毎回付与なら不要。
  5. items の key は hat / ribbon / crown / glasses と仮置き (docs/mock が無かったため値は依頼文のもの)。
  6. 着せ替えの部位排他 (帽子は 1 つだけ等) は未対応。
