# ゲーム設計

作成日: 2026-11-15
ステータス: 決定

## 論点

購入抑制 (マイナス要素が前提) をどうゲーム化して継続させるか。

## 選択肢（任意）

育てる対象の候補: ペット、惑星、街、植物。

## 決定

- **ペットを育てる。** 大学生はペットを飼えないことが多く刺さる。参考: Bongo Cat (https://store.steampowered.com/app/3419430/Bongo_Cat/?l=japanese) のキャラクター機能を取り入れる。
- **着せ替えで拡張性を持たせる。** 着せ替えアイテムはゲーム内通貨で購入する。
- マイナス要素が前提のプロダクトなので、**プラスを得やすくする**。
  - プラス: 買い物上手スコア、ログイン報酬 (+20、自動)、買い物に行かなかった日 (+30、ログイン時に自動)、買い物リストの作成・閲覧。
  - 報酬は自動で付与し、演出で見せる。文字が出てフェードアウトし、コインがコイン表示へ吸い込まれる。ボタン操作は不要。
  - 「買い物に行かなかった日」の判定は仮決め: ログイン時に、直近で買い物の結果判定がなければ付与する。
  - マイナス: 予算超過、不要購入品、コンビニ立ち寄り。
- ポイントの具体値と買い物上手スコアの計算式は Phase 1 で確定する (ゲーム担当)。
- キャラクター素材は AI 画像生成で用意する (C、必須ではない)。
- スコアの抜け穴: 予算とリストだけだと、セール品を買った、または予定の品を買わなかっただけで「上手」になりうる。MVP はこのまま進め、緩和として「リスト消化率」を加点条件に入れる案を Phase 1 のスコア仕様で検討する。
- 余裕があれば、レシートを画像を読めるAIで分類し、お菓子・嗜好品の割合を判定に使う (REQ-012)。API コストは少額なので許容する (2026-11-15)。判定は減点より、ペットの一言コメントを中心にする。
