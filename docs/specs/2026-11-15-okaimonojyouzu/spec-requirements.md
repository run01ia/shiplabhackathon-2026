## 背景

実店舗特化の購入抑制アプリ。20 代の大学生・新社会人 (一人暮らし、自己管理が苦手だが支出管理の意識はある) が、買い物リストと予算を決め、守れたらプラス、破ったらマイナスとしてゲーム化して購入を抑制する。ペットを育て、着せ替えで拡張する。

- コンセプト・ペルソナ・スコープ: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)
- 優先度: A=絶対 (これがないと発表できない) / B=できれば / C=時間があれば
- スコープ外: 何を買ったかの記録、過去の購入履歴、ポイントの増減履歴 (MVP のため持たない)

## 要件一覧

### REQ-001: ユーザー認証

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: A

ユーザーがサインアップ・ログイン・ログアウトできる。データはユーザーごとに分離する。

受け入れ条件:
- メールなどでサインアップできる
- ログイン後、自分のデータだけが見える
- ログアウトできる

### REQ-002: 買い物リスト作成

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: A

買い物前に品目のリストを作る。品目の追加・編集・削除と、購入済みチェックができる。

受け入れ条件:
- 品目を追加・編集・削除できる
- 買い物中に購入済みにチェックできる
- リストはユーザーごとに保存される

### REQ-003: 予算設定

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: B

今回の買い物で使える予算を設定する。品目の合計と予算の残額を表示する。

受け入れ条件:
- リストごとに予算を設定できる
- 品目の金額合計と残額が見える

### REQ-004: リスト外購入の妥当性判断

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: A

買い物中にリストにない品目を買いたくなったとき、追加して「本当に必要か」を確認する。買ったものは不要購入として記録できる。

受け入れ条件:
- リスト外の品目を追加できる
- 追加時に「ほんとうに必要？」を確認する画面が出る (質問は 1 つだけ。理由の選択や入力は求めない)
- 不要と判断した購入を記録できる

### REQ-005: 買い物結果の入力と判定

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: A

買い物終了時に実際の支出額を入力し、予算内か、不要購入があったかを判定する。判定結果はポイントに反映する。

受け入れ条件:
- 支出額を入力できる
- 予算超過を判定できる
- 判定結果が REQ-006 のポイントに反映される

### REQ-006: ポイントとゲーム内通貨

関連discussion: [discussion/game-design.md](./discussion/game-design.md)

優先度: A

プラス要素でポイントが貯まり、マイナス要素で減る。ポイントはゲーム内通貨として管理する。

受け入れ条件:
- ログイン時に、ログイン報酬 (+20) が自動で付与される (ボタン操作は不要)
- ログイン時に、買い物に行かなかった日の報酬 (+30) が自動で付与される
- 付与時は報酬の文字が出て、コインがコイン表示に吸い込まれる演出が流れる (文字はフェードアウト)
- リスト作成・閲覧でポイントが付く
- 予算内達成でポイントが付く
- 予算超過・不要購入・コンビニ立ち寄りで減る

### REQ-007: ペット育成画面

関連discussion: [discussion/game-design.md](./discussion/game-design.md)

優先度: A

ペットを表示し、買い物の結果に応じて育つ。通貨とスコアを表示する。

受け入れ条件:
- ペットが表示される
- 通貨とスコアが見える
- ログイン時の報酬演出が見られる

### REQ-008: 着せ替え

関連discussion: [discussion/game-design.md](./discussion/game-design.md)

優先度: B

ゲーム内通貨で着せ替えアイテムを購入し、ペットに着せられる。

受け入れ条件:
- アイテム一覧を見られる
- 通貨が足りれば購入できる
- 購入済みアイテムを着せ替えられる

### REQ-009: スーパー付近で買い物画面へ自動遷移

関連discussion: [discussion/location-alert.md](./discussion/location-alert.md)

優先度: B

よく行くスーパーを登録する。登録したスーパーの近くでアプリを開いたら、自動で買い物中の画面へ遷移する。リストが未作成なら、先に「リストは作りましたか？」と促す。自動検知はアプリを開いている間だけ (Web の制約)。

受け入れ条件:
- 現在地をスーパーとして登録できる
- 登録店の近く (約 200m 以内) でアプリを開くと、買い物中の画面へ自動で遷移する
- リストが未作成なら、リスト作成を促してから遷移する

### REQ-010: コンビニ入店アラート

関連discussion: [discussion/location-alert.md](./discussion/location-alert.md)

優先度: C

**見送り** (Web アプリでは自動検知できないため)。必要なら「コンビニに寄った」ボタンを手動で押し、「買う目的はありますか？」と警告してマイナスを記録する形に縮小する。

受け入れ条件:
- (縮小案) 手動ボタンで警告が出て、マイナスが記録される

### REQ-011: コスパ悪商品の抑制リマインド

関連discussion: [discussion/location-alert.md](./discussion/location-alert.md)

優先度: C

ペットボトルなどコスパの悪い商品を買いにコンビニへ行くことを、リマインド通知で抑制する。

受け入れ条件:
- リマインド通知を受け取れる

### REQ-012: レシートAI判定

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: C

レシートを撮影すると、画像を読めるAI (マルチモーダル) が品目と金額を読み取り、「食材 / 日用品 / 飲み物 / お菓子・嗜好品」に分類する。分類結果を買い物上手のスコアとペットの一言コメントに反映する。予算とリストだけでは見抜けない「不要なお菓子を買っていないか」を判定するのが狙い。手入力を省く効果もある。

受け入れ条件:
- レシート画像から品目、金額、分類を取得できる
- 分類結果 (お菓子・嗜好品の割合など) がスコアに反映される
- ペットが結果に応じた一言コメントを出す (減点より、コメントを中心にする)

### REQ-013: 家の在庫管理

関連discussion: [discussion/concept-and-scope.md](./discussion/concept-and-scope.md)

優先度: C

家にある食材を管理し、重複買いを防ぐ。

受け入れ条件:
- 在庫を登録・更新できる
- 買い物リスト作成時に在庫を参照できる
