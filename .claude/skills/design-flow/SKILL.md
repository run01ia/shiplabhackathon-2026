# design-flow

新規機能または大きな変更について、`new-spec` と `impl-plan` を順に進め、実装まで一気に行う入口スキル。時間が限られているため、**人間の合意待ちで止まらない**。

## 原則

- 不明点は質問で止まらず、妥当な既定値を採用して discussion に「前提・仮決め」として記録する。
- 技術選定は候補とトレードオフを discussion に残し、AI が決定する。
- 設計完了時に「設計完了レポート」をアーティファクトで共有する。これは報告であり、承認待ちではない。共有後はそのまま実装へ進む。
- 人間から修正指示があった場合は、該当する仕様・設計を更新し、影響するタスクを直す。

## 責務分担

```
new-spec
  要件定義: 背景、利用者、スコープ、受け入れ条件、REQ-ID、技術的制約
impl-plan
  概要設計: 技術選定、アーキテクチャ、フォルダ構成、処理フロー、動作確認（正常系）、domain のテスト対象
  詳細設計: REQ-IDごとのインターフェース、データ、状態、例外、動作確認
  実装計画: タスク定義、依存関係、担当、進捗、完了時の動作確認
```

`impl-plan` の成果物は対応する `docs/specs/{spec-folder}/` と 1:1 に対応させる。設計・実装計画からは必ず仕様要件の REQ-ID にリンクする。

## 進め方

### 1. 要件定義（new-spec）

既存の仕様フォルダがなければ `new-spec` で `spec-requirements.md` と `tech-requirements.md` を作る。既存の場合は内容を確認して再利用する。

- 目的、対象利用者、スコープ外、受け入れ条件を明確にする。
- 要件は `REQ-XXX` で一意に識別する。
- 仮決めした事項は discussion に記録する。

### 2. 概要設計（impl-plan）

`summary.md` に、技術選定、アーキテクチャ、変更対象、処理フロー、正常系の動作確認（画面操作または API 呼び出しと期待結果）を記載する。

### 3. 詳細設計・タスク定義（impl-plan）

`detailed-design.md` に実装可能な詳細を定義し、それを根拠にタスクを作成する。全タスクの依存関係・並列可否・担当・完了時の動作確認を定めた `orchestration.md` は、タスク定義がそろった後に作成する。

### 4. 設計完了レポート（アーティファクト）

詳細設計とタスク定義が終わったら、結果を**アーティファクトで 1 ページにまとめて共有する**。公開前に `mcp__claude-artifacts__guide` の `pages` と `design` を読み、そこに書かれた規則に従うこと。

載せる内容:

- **何を作るか**: 目的、対象利用者、スコープ外 (3〜5 行)
- **要件一覧**: REQ-ID、要約、優先度、受け入れ条件
- **技術選定とアーキテクチャ**: 構成図 (guide の `diagrams` に従う)、選定理由
- **処理フロー・画面操作の流れ**: 正常系の動作確認の手順と期待結果
- **タスク一覧**: 番号、概要、担当、依存関係、並列可否
- **仮決めした事項**: 人間に見直してほしい前提を目立たせる (承認待ちではない)
- 元ドキュメントへのパス (`docs/specs/...`, `docs/impl-plan/...`)

共有後はレポートの返信を待たずに実装へ進む。

### 5. 実装（impl-plan C）

`orchestration.md` の波に従って実装する。並行実装、PR、マージ、進捗更新の手順は `autopilot` skill に従う (タスクを Issue にし、1 Issue = 1 サブエージェント = 1 worktree)。

**テストは `backend/src/domain/` の純粋関数にだけ、最低限を書く** (テスト方針は [docs/architecture.md](../../../docs/architecture.md) の「テスト方針」)。それ以外は、タスクごとに画面または API から正常系を確認し、1 タスク単位でコミットする。

## 運用上の原則

- 調査や選択肢比較は必要に応じて補助エージェントに任せてよい。成果物の統合と最終判断はこのフローの担当エージェントが行う。
- 実装中に設計前提が変わった場合は、先に該当する仕様・設計を更新してから実装を続ける。
- 小さく明確な修正では、必要な節だけ更新してよい。ただし REQ-ID と設計・実装計画のリンクは維持する。
